Start with a small, runnable example of the prediction interface.

This example returns zero for every requested reading. It demonstrates the exact array layout without a model API key, simulation cache, or running laboratory. It does not measure predictive accuracy.

Run from a checkout

git clone https://github.com/swpo/physim.git
cd physim
python3 -m venv .venv-docs
.venv-docs/bin/python -m pip install numpy
.venv-docs/bin/python docs/examples/predictor.py docs/examples/request.json

On Windows, use .venv-docs\Scripts\python for the environment's Python executable.

Or download predictor.py and request.json into the same directory and run python predictor.py request.json in an environment with NumPy installed.

The output contains these shapes and "all_finite": true:

(64, 3, 12, 13)  # device0: 3 times, 12 ports, 13 slots
(64, 2, 12, 19)  # device1: 2 times, 12 ports, 19 slots
(64, 1, 12, 2)   # global:  1 time,  12 ports,  2 statistics

Reproduce the physical reference locally

The packaged runtime now loads a self-contained bundle of the prepared fields, apparatus, 15 programs, and retained truths. The runtime has passed a clean installation check. Code is Apache-2.0 and data are CC-BY-4.0. The world dataset is now published, including the original reference, BF, and XV preparations. Anonymous downloads and offline reference checks are verified.

From a checkout with Python 3.12, install the workspace and fetch the original reference:

uv sync --locked
uv run physim catalog --repo seanpohorence/physim-worlds \
  --revision dcd6abd5eae76a47f326c70518315d2d1e101d86
uv run physim fetch --repo seanpohorence/physim-worlds \
  --revision dcd6abd5eae76a47f326c70518315d2d1e101d86 \
  --path bundles/p4g2_044/0c133190c1c86450f56651b47e35f0d729f6a84c7c51a4bc7d91850a9a392ff2 \
  --profile evaluation
# Use the directory printed by fetch:
uv run physim inspect --bundle /path/printed/by/fetch
uv run physim demo --bundle /path/printed/by/fetch --output outputs/reference-demo

The demo checks seven interface cases and reproduces the persistence predictor’s 15-case score of 0.8271209896216252, using four forecast members and two retained truths per case. It makes no model API calls and advances no new simulation. Model results use 64 forecast members.

To run new native physics explicitly, use physim experiment with scripts/physim/examples/short-experiment.json. To evaluate submitted Python, build the versioned Docker sandbox and use physim validate and physim grade. The repository README contains the complete commands.

Choose a world for a model evaluation

The environment and portable preparation workflows are being contributed to Prime Intellect in draft PR #22. During review, the released package and this checkout remain available. Blobkit, exploratory research, and this documentation stay in the personal repository.

The environment requires an explicit preparation. It does not scan the registry or run all eval-ready worlds by default. After building the Docker images and configuring a model provider, select one of configs/physim/p4g2_044.toml, bf_trail_lab.toml, or xv_rotor_lab.toml. Missing selection is an error.

uv run eval @ configs/physim/bf_trail_lab.toml --model YOUR_MODEL_ID

The supplied configs allow 1,000 experiments, 50,000 integrated simulation time units, 1,024 model turns, and a 24-hour rollout timeout. They make paid model calls. Longer investigations can raise the experiment, model, and execution limits together; the physical horizon of each experiment remains 50 time units. See the configuration guide and standalone release for installation and runtime setup.
