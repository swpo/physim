Reproduction connects the code, physical data, and experimental record at exact versions.

GitHub hosts code and documentation. The Hugging Face dataset holds the world registry and self-contained laboratory bundles. Code is Apache-2.0; data are CC-BY-4.0. The published packages and bundles support use without the historical research checkout.

The registry and its contents

{{registry_counts}}

The two statuses are defined in Evaluation. World records link their available generation recipes, runs, candidate measurements, checkpoints, and harvested artifacts. Shared content is stored once by hash. Missing historical settings or checkpoints are marked partial; future plans are kept outside the registry.

Recipe records retain Python source, starting genomes, settings, callback state, and implementation versions. Candidate records retain parentage, seeds, metrics, and selection evidence. Reading the registry does not execute archived code; reproducing a generation run requires explicitly exporting and running its recipe.

What a result must identify

ObjectWhat it fixes
WorldGenome, simulator revision, and numerical profile.
PreparationExact initial fields, apparatus, source, time origin, and noise policy.
Evaluation suitePreparation reference, API contract, programs, score groups/scales, truth set, and aggregation.
RunPredictor artifact, observations, model/harness configuration, budgets, validity, and scores.

Human-readable names aid browsing; hashes and exact code/data revisions identify what was used. Changing a sensor layout, starting state, or score definition creates a new corresponding identity. A mutable “latest” label is insufficient for reporting a result.

Laboratory bundles

bundles/<preparation-name>/<revision>/
  manifest.json       # identities, numerical profile, source versions and hashes
  world.json          # field genome
  preparation.npz     # exact initial fields
  apparatus.json      # probes, source and control mapping
  suite.json          # programs, contract, score groups and scales
  truth/              # independent reference realizations
  checks.json         # reproduction and validation evidence

The loader requires a full dataset commit, downloads only the selected profile within byte caps, verifies hashes, and checks array headers before allocation. Verified cached bundles work with --offline. Bundles contain data rather than executable Python.

Evaluation configs pin scientific data revision dcd6abd5eae76a47f326c70518315d2d1e101d86. Later dataset documentation updates preserve these payloads and catalog rows. All three preparations passed anonymous download, offline loading, reference-score reproduction, and short native simulation checks. Native reproduction pins NumPy 2.5.2 and SciPy 1.18.0 and verifies simulation source hashes.

The published configs select the historical fixed-source-v1 apparatus. Their source remains stationary while probes move; the original agent contract describes that version. The updated centered-source apparatus is implemented in the development code; new preparations, reference observations, and rollouts are pending. Selecting an old bundle preserves its original contract and results.

Start with the prediction interface

This example returns zero for every requested reading. It demonstrates the exact array layout without a model API key, simulation cache, or running laboratory. It does not measure predictive accuracy.

Run from a checkout

git clone https://github.com/swpo/physim.git
cd physim
python3 -m venv .venv-docs
.venv-docs/bin/python -m pip install numpy
.venv-docs/bin/python docs/examples/predictor.py docs/examples/request.json

On Windows, use .venv-docs\Scripts\python for the environment's Python executable.

Or download predictor.py and request.json into the same directory and run python predictor.py request.json in an environment with NumPy installed.

The output contains these shapes and "all_finite": true:

(64, 3, 12, 13)  # device0: 3 times, 12 ports, 13 slots
(64, 2, 12, 19)  # device1: 2 times, 12 ports, 19 slots
(64, 1, 12, 2)   # global:  1 time,  12 ports,  2 statistics

Reproduce a reference score locally

The original p4g2_044 bundle supplies its saved fields, apparatus, 15 programs, and retained truths. The demo below uses these retained measurements to check the interface and scoring without advancing a simulation.

From a checkout with Python 3.12, install the workspace and fetch the original reference:

uv sync --locked
uv run physim catalog --repo seanpohorence/physim-worlds \
  --revision dcd6abd5eae76a47f326c70518315d2d1e101d86
uv run physim fetch --repo seanpohorence/physim-worlds \
  --revision dcd6abd5eae76a47f326c70518315d2d1e101d86 \
  --path bundles/p4g2_044/0c133190c1c86450f56651b47e35f0d729f6a84c7c51a4bc7d91850a9a392ff2 \
  --profile evaluation
# Use the directory printed by fetch:
uv run physim inspect --bundle /path/printed/by/fetch
uv run physim demo --bundle /path/printed/by/fetch --output outputs/reference-demo

The demo checks seven interface cases and reproduces the persistence predictor’s 15-case score of 0.8271209896216252, using four forecast members and two retained truths per case. It makes no model API calls and advances no new simulation. Model results use 64 forecast members.

To run new native physics explicitly, use physim experiment with scripts/physim/examples/short-experiment.json. To evaluate submitted Python, build the versioned Docker sandbox and use physim validate and physim grade. The repository README contains the complete commands.

Run a model evaluation

The environment and portable preparation workflows are being contributed to Prime Intellect in draft PR #22. During review, the released package and this checkout remain available. Blobkit, exploratory research, and this documentation stay in the personal repository.

After building the Docker images and configuring a model provider, select a preparation explicitly with configs/physim/p4g2_044.toml, configs/physim/bf_trail_lab.toml, or configs/physim/xv_rotor_lab.toml. For example:

uv run eval @ configs/physim/bf_trail_lab.toml --model YOUR_MODEL_ID

The supplied configs allow 1,000 experiments, 50,000 integrated simulation time units, 1,024 model turns, and a 24-hour rollout timeout. They make paid model calls. Longer investigations can raise the experiment, model, and execution limits together; the physical horizon of each experiment remains 50 time units. See the configuration guide and standalone release for installation and runtime setup.

Run a world-generation recipe

After uv sync --locked, a small CPU recipe exercises Blobkit's simulation, search, and registry workflow:

uv run blobkit generate generators/physim/recipes/small_search.py --registry outputs/small-search
uv run blobkit registry verify outputs/small-search

Its short-run mass metric demonstrates the machinery; it is not a measure of scientific interest. A recipe supplies build_recipe() returning a SearchRecipe, with customizable evaluation, scoring, proposal, selection, and harvest functions. Checkpoints allow a run to pause and resume with recorded state. The Blobkit package documentation describes the interfaces and optional backends.
