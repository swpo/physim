We evaluated seven models using Prime Agent in the BF laboratory. Each model received an interface-only description, conducted experiments, and submitted a predictor for evaluation on 15 held-out programs, using 64 forecast members and two independent truth realizations per program.

We report one completed rollout per model as a case study of experimental strategies and prediction failures. Without repeated rollouts or evaluation across worlds, these results do not estimate typical model performance or establish a benchmark ranking.

Where the predictions work

Aggregate rewards conceal substantial differences between programs. Several predictors reproduce undisturbed readings closely but lose accuracy when interventions are combined with movement. A case score includes complete trajectories from all measurement interfaces; the individual traces below illustrate specific errors within those scores.

Two examples connect these failures to the submitted code. Qwen 397B retrieves a stored pulse response whose amplitude is much too large for the request. GLM adds separate pulse and movement responses, which loses the distinction between moving the source before injection and moving it afterward.

What each agent built

Qwen 35B: a compact predictor with an untested branch

Qwen 35B ran 56 experiments, mostly individual injections. Its final program hard-codes baseline readings and applies simple corrections for interventions, with independent noise added to predictions. Injection effects last only through the injection interval; the predictor does not model a persistent response afterward.

The public validation passed, but grading exercised a branch those checks had not reached. For a port-2 injection, the predictor writes to sensor slot 2 even for the global interface, which has only two slots. Four programs fail with an index error. The eleven executable programs also have relatively large errors, so repairing that branch alone would not establish an accurate model. The submitted program is retained unchanged.

Qwen 397B: a response library with poor coverage

The larger Qwen ran 214 experiments, including injections, adjustments, and combinations. Its final predictor uses a bank of 96 injection trajectories: it selects a nearby amplitude and duration for the requested device and port, then interpolates the stored readings in time. It handles only the first injection, ignores adjustments, and does not shift the response to the requested injection time.

The library starts at amplitude 0.5, while the three trail cases use 0.002, 0.01, and 0.05. Reusing the nearest trajectory without amplitude rescaling produces large overestimates. Those three cases contribute about 86% of its total energy. No-action and strong-activator predictions are much better. The limitation is visible both in the code and in the common-case comparison above.

Luna: delegated experiments and a hybrid predictor

Luna delegated baseline, injection, and adjustment studies to three child agents and accumulated 1,327 experiments. It combined empirical response kernels with tree models for adjustments and nonlinear residuals, plus a specialized response model for port 2. Its predictor anchors the no-action forecast to measured baseline behavior and adds temporally correlated noise.

One public validation exposed a reproducibility failure: identical requests and seeds did not return bitwise-identical results. Luna changed the tree prediction setting to a single worker and passed subsequent checks. Its final reward is 0.874. It performs well on undisturbed readings and several isolated interventions, but moving before a pulse remains its highest-error case. Delegation expanded the experimental coverage; this single run does not isolate its contribution to the score.

Grok: an explicit spatial hypothesis

Grok ran 80 experiments and fitted a spatial model with hypothesized sensor positions, Gaussian source profiles, and four coupled response variables. It represented adjustments as geometric transformations and retained the injection location when predicting later movement. This structure was constructed by the agent from the interface and observations; the underlying geometry was not supplied in its prompt.

The submitted model is an approximation, not a recovery of the simulator. For example, it represents the global outputs using two spatial locations rather than the world's actual aggregate measurements. It passed both public validations and scored 0.864. A movement-only case is predicted well, while delayed injection, two sources, and moving before a pulse produce larger errors.

Terra: extensive data collection and learned action history

Terra ran 1,594 experiments, including 769 programs combining injections and adjustments. It built features from past actions using decays, oscillations, and accumulated inputs, then fitted neural-network ensembles with separate models for injection, adjustment, and mixed programs. A specialized component handles the port-2 response.

Its first public validation rejected an oversized artifact. Terra reduced it and passed two later validations before submitting. The final predictor returns the same mean trajectory for all 64 forecast members, expressing no predictive spread. Its reward is 0.768, with low error on undisturbed readings but larger errors for movement and multiple sources. The roughly four-hour investigation and large dataset did not translate into uniformly better predictions in this rollout.

Sonnet: boosted trees and correlated forecast variation

Sonnet ran 1,600 experiments, with 1,034 combining injections and adjustments. After exploring several fitted models, it submitted gradient-boosted trees for individual channels and sensor positions. Inputs summarize action history over several decay timescales. The predictor then adds correlated variation across sensor positions and time using a separate residual model.

Both public validations passed. The investigation took about four hours and fifty-three minutes and produced a reward of 0.863. Among these particular predictors, Sonnet has the lowest energy on delayed injection and the high trail pulse, while its no-action error is larger than those of the other fully executable predictors. Its strengths differ from Luna's and Grok's despite their similar aggregate rewards.

GLM: a strong additive model with a causal blind spot

GLM ran 187 experiments. It fitted damped oscillations and a decaying component to baseline readings, then built response families for injections and adjustments. The final predictor combines those responses, scaling injection amplitude and approximating duration through small time increments. Only four of its experiments combined injections and adjustments.

It passed both public validations and achieved the highest reward in this set, 0.908. Yet its additive construction produces effectively identical predictions for opposite orders of simultaneous movement and injection. The world's responses differ because the source location is fixed when injection is initiated. Moving before a pulse is GLM's highest-error case. A good average forecast therefore coexists with a missed causal distinction in the apparatus.

Resources and interpretation

{{case_study_tokens}}

Token totals come from native streaming usage records, including child agents. Fresh input includes cache writes; cache reads are counted separately. Output includes reasoning tokens where the provider reports them in its output total. Requests without usage are not reconstructed. Different provider accounting and cache policies limit cost comparisons.

These runs illustrate several workable approaches and concrete failure modes. Increasing experimental volume alone did not guarantee better predictions, and a strong average score did not imply correct treatment of every intervention. Public validation caught reproducibility and artifact problems, but its finite set of requests did not catch Qwen 35B's indexing bug.

Each model has only one selected rollout in one prepared world. There are no replicate-based uncertainty estimates, and GLM's blind retry adds a selection caveat. Repeated runs across BF, XV, and p4g2_044 are needed before making claims about typical performance, reliability, or cost–performance tradeoffs.
