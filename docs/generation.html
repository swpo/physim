Generating worlds

World generation searches for field dynamics worth investigating, then measures what those dynamics actually do.

A reusable generation package

Blobkit provides simulation, evolutionary search, metrics, scheduling, checkpoints, and harvesting. A recipe supplies Python functions for its measurements, fitness, mutation or recombination, selection, and harvest criteria. Defaults are available; new behavior can be written directly in Python.

The registry stores each recipe's code and starting genomes, then links its runs, measurements, parentage, and harvested worlds. A short CPU example exercises this workflow:

uv run blobkit generate generators/physim/recipes/small_search.py --registry outputs/small-search
uv run blobkit registry verify outputs/small-search

The example's short-run mass metric demonstrates the workflow; it is not a quality benchmark. Runs can pause at a generation checkpoint and resume with the recorded recipe and implementation. Custom metrics and search policies belong to the recipe, while the package executes the reusable search loop.

A genome describes activators, channels, coefficients, and coupling structure. Search operators can mutate parameters, add or remove channels, combine systems, or introduce interactions. Numerical checks reject unsupported or unstable candidates before more expensive characterization.

Search descriptors are evidence to investigate

Descriptors can organize candidates by movement, growth, timescales, or spatial structure. Keeping diverse candidates helps preserve distinct behaviors instead of optimizing a single appearance. A descriptor bin is a category in a search archive; it is not a physical compartment.

Search fitness measures the criteria used by a generation campaign. It is separate from a prediction score. A high search score alone does not establish a causal mechanism, a robust phenomenon, or a usable evaluation task.

From candidate to experimental world

A useful world needs a reproducible numerical specification and an exact preparation. Characterization should distinguish observations from mechanistic hypotheses, include controls, and record where behavior fails or changes with preparation.

Apparatus and evaluation cases follow the physics. For example, if an observed pulse effect depends on location, probe placements should resolve that spatial difference. If intervention timing matters, the selected readings must resolve the relevant times.

From experimental world to prediction suite

The suite fixes the action/query programs, score groups, scales, and truth evidence. Simple predictors and deliberately incomplete physical predictors test whether the score responds to the intended errors. Case changes produce a new suite revision rather than silently changing an existing result.

Three preparations have a complete evaluation path: p4g2_044, bf_trail_lab, and xv_rotor_lab. BF and XV preserve fresh intervention studies, mechanism controls, frozen suites, and model pilots. Other registry records are preserved worlds and do not need an evaluation suite.
