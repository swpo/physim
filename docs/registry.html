A registry of reproducible worlds

The registry keeps genomes, generation recipes, and run history together with prepared evaluation worlds and their evidence.

Published and verified. Download the world registry and three evaluation preparations on Hugging Face. The snapshot includes all 24 records and their available provenance. Anonymous download, file integrity, offline loading, and native reference checks passed. Code is Apache-2.0 and data are CC-BY-4.0.

The distribution split is GitHub for code, schemas, and documentation, and a Hugging Face dataset repository for world bundles and a browsable catalog. Bundle identity and offline loading are independent of the host.

Preserved means the world and its available provenance are stored. Any world can be preserved, including simple controls and example harvests.

Eval-ready means an exact preparation, apparatus, prediction suite, truth data, and validation evidence are linked and ready to use with the evaluation environment. This label applies to that preparation and suite; it does not imply public release or suitability for every task.

The registry records what exists. Scientific observations and generation history stay with their evidence; exploratory shortlists and future plans are kept outside the registry.

Generation history

The prepared evaluation records below are linked to a generation registry. That registry also contains genome, recipe, generation-run, candidate, checkpoint, and harvested-world records. A recipe can produce many runs and a run can produce many worlds; shared content is stored once by hash.

Recipe records retain Python source, initial genomes, settings, callback state, and implementation versions. Candidate records retain parents, simulation seeds, metrics, and selection evidence. Registry reads never execute archived code. Explicit recipe export and execution support reproduction and extension.

The current catalog contains 24 world records describing 19 distinct genomes: 21 preserved records and three eval-ready preparations. It includes the 15 packaged worlds, the p4g2_044 reference, and a small executable search example with recorded provenance. Missing historical settings or checkpoints are marked partial. A harvested genome needs its own preparation and validation before becoming an evaluation task.

The bf_trail_lab and xv_rotor_lab preparations are also eval-ready. Each preserves 11 prediction programs, independent grading truth, fresh scientific observations, mechanism controls, and a completed model pilot. BF uses four anonymous ports and XV six. Their complete bundles and preparation recipes can be reconstructed from registry artifacts.

Four evaluation identities

ObjectWhat it fixes
WorldGenome, simulator revision, and numerical profile.
PreparationExact initial fields, apparatus, source, time origin, and noise policy.
Evaluation suitePreparation reference, API contract, programs, score groups/scales, truth set, and aggregation.
RunPredictor artifact, observations, model/harness configuration, budgets, validity, and scores.

Human-readable names help browsing. Content hashes and exact code/data revisions make results reproducible. A changed sensor layout, prepared state, or score definition must produce a different corresponding identity. A mutable “latest” label is insufficient for a reported result.

The first reference bundle

bundles/p4g2_044/<revision>/
  manifest.json       # identities, source revisions, files and hashes
  world.json          # genome and numerical profile
  preparation.npz     # exact initial fields
  apparatus.json      # probes, source and control mapping
  suite.json          # programs, contract, groups and scales
  truth/              # independent reference realizations
  checks.json         # reproduction and validation evidence

The original reference bundle contains 3,732,420 bytes of payloads plus its manifest. The simulation-only profile uses 2,751,237 bytes. The original field hash and all 15 retained truth files are preserved; the historical 795 MB cache is unnecessary after export.

The loader requires a full repository commit, downloads only the requested profile with byte caps, verifies every hash, and checks array headers before allocation. Verified cached bundles work with --offline. Data bundles supply no executable Python.

Reference material and held-out evaluation

The first bundle is intended as an openly reproducible reference example. Results on its disclosed world and suite should be labeled as development results. Future claims about unfamiliar systems need distinct, appropriately held-out worlds or preparations.

Unreleased challenge preparations and truth belong in a separate access-controlled grader store. The evaluated agent receives its contract, observations, and own artifact; the trusted host resolves the physical data.

Reproduction and publication

The original reference reproduces the saved persistence score exactly, passes all seven public interface checks, and matches the original simulator bit for bit on short no-action, injection, and probe-adjustment runs. The clean installation also performs a new native experiment without the research tree or model credentials.

Evaluation configs pin data revision dcd6abd5eae76a47f326c70518315d2d1e101d86. Later documentation updates add installation and contribution guidance while preserving all scientific payloads and catalog rows. All three preparations pass download, offline-cache, reference-score, and short native simulation checks. The public Physim release includes checksummed packages, Docker build instructions, and configs selecting each preparation explicitly.

The catalog metadata records the published revision, verified bundle identities, and capabilities. Additional worlds need their own preparation and evidence.
