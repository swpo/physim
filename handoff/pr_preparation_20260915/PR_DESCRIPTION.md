Physim asks an agent to investigate an unfamiliar stochastic physical system through experiments, then submit a Python predictor for new interventions and sensor queries. The task uses stock Verifiers' coding harness and Docker runtime. Laboratory operations stay on the trusted host; physical state and grading truths are not mounted into the agent or predictor container.

This adds the installable `physim` taskset, explicit configs for three published preparations, Docker build support, and matching generation/preparation/validation workflows under `generators/physim/`. The shared simulator, Blobkit 0.3.5, is a separately published, SHA-256-pinned dependency. World definitions, exact preparations, frozen suites, and provenance live in the [public HF registry](https://huggingface.co/datasets/seanpohorence/physim-worlds).

Select `configs/physim/p4g2_044.toml`, `bf_trail_lab.toml`, or `xv_rotor_lab.toml` and override the model. Missing world selection is an explicit error; the environment does not silently scan or evaluate the registry. One evaluation example is a complete investigation/submission episode, whose predictor is graded on 15 reference programs or 11 BF/XV programs. The full-eval convention is one example and one rollout. Defaults allow 1,000 experiments, 50,000 simulation time units, 1,024 model turns, and a 24-hour rollout; the README explains longer investigations and bounded wiring smokes.

The scientific score is lower-is-better joint energy, mapped to reward as `1 / (1 + error)`. An otherwise completed attempt without a valid predictor receives zero reward. Infrastructure errors use Verifiers' existing error handling. These are disclosed development preparations, not a held-out generalization benchmark.

Validation: a fresh candidate installation uses the public Blobkit wheel and current Verifiers 0.3.1. All three published worlds pass their reference scores and fresh native experiments. Both BF/XV preparation files reproduce byte for byte from pinned HF inputs. Both full 11-program truth/control rebuilds, native validations, and registry round trips pass, with all 22 grading-truth archives reproduced byte for byte. BF's mechanism control reproduces its recorded effect; the portable search example also completes. The two generic upstream package checks and repository-wide Ruff lint/format checks pass. No per-environment unit tests or upstream CI changes are included.

Two fresh DeepSeek V4 Flash smokes (`-n 1 -r 2`, four turns) completed with zero infrastructure errors; neither delivered a predictor, so both received zero reward. Together they cost $0.0027. This checks integration, not prediction quality. Earlier longer BF/XV pilots submitted valid predictors; their settings, scores, and limits are recorded in the [scientific report](https://github.com/swpo/physim/blob/main/handoff/eval_preparation/REPORT.md). [Public release setup](https://github.com/swpo/physim/releases/tag/physim-v0.12.2) and [Linux installation/Docker verification](https://github.com/swpo/physim/actions/runs/34970845043) are also available.

Four numerical/reference modules retain their exact source bytes because published manifests bind those hashes; the environment's Ruff configuration excludes those files from formatting. Changes to numerical semantics should introduce new identities and validation. Maintainer review is welcome on selecting the explicit world config in Prime's external evaluation runner and provisioning the documented Docker images.
